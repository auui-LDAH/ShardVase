# 战略方针：完全开源 + 简化 VM + 抬高破解成本

> **方针表述（用户 2026-09-21 定调）**：
> "我要完全开源，并简化 VM，加高破解者的成本 ——
> **我要让破解者明知知道这么防御的，但还是要大量的时间和资源去破解。**"
>
> **这本质上是 Kerckhoffs 原则**：安全性只依赖**密钥**，不依赖**设计保密**。
> **本文档的目的**：用实测判断该方针**能否成立**、**瓶颈在哪**、**要补什么**。

---

## 0. 结论：方针**可以成立**，但当前实现有一个**必须修的致命弱点**

| 判定 | 内容 |
|------|------|
| ✅ **方针本身成立** | 完全开源后仍有 5 条防线**不依赖保密**（见 §2）|
| ✅ **简化 VM 是合理推论** | 源码公开后，VM 复杂度对**静态**理解的价值归零；简化可换取可维护性 |
| ❌ **但有一个致命弱点** | **per-build 秘密可被"两次构建 diff"直接定位**（实测，见 §3）|
| 🔧 **必须补的** | 让 diff **无法定位**秘密 + 节名**不泄露用途**（见 §4）|

> **如果不修 §3 的弱点**，方针会退化为：
> "源码公开（理解成本 = 0）" + "秘密位置已知（每次只需读一小段）"
> —— 攻击者的**增量成本趋近于零**，与原意相反。

---

## 1. 该方针下的成本模型（重新定义"防线"）

**Kerckhoffs 原则下，"防线"的判据变了**：

> 一条防线只有满足「**攻击者完全知道其原理，仍无法绕过**」
> 才在完全开源后**仍然有效**。

按这个判据重新评估现有六道防线：

| # | 防线 | 开源后 | 判定依据 |
|---|------|--------|----------|
| **①** | 符号不落地 | ✅ **有效** | C 无元数据 + `/DEBUG:NONE` —— 是**编译期事实**，与保密无关。实测 0/32 可见 |
| **②** | 指针不集中 | 🟡 **部分** | 表结构公开 → 但 `s_perm` 每构建变，**仍是动态障碍** |
| **③** | 判定不单点 | ✅ **有效** | 知道"判定在 VM 内"**≠** 能改 VM 结果（VM 是动态过程）|
| **④** | 完整性校验 | ✅ **有效** | 算法公开不影响"CRC 必须自洽" —— 攻击者仍须重算 |
| **⑤** | **每构建变化** | ✅ **有效** ★ | **唯一的核心杠杆** —— 不依赖保密，靠随机化 |
| **⑥** | 理解成本 | ❌ **归零** | 完全开源 = 可直接读源码 |

**关键**：**⑤ 是唯一在完全开源后仍然强大的杠杆**。所以方针的全部重量压在它身上。

---

## 2. 完全开源后，攻击者"仍然必须做"的事

```
【不需要做了】（源码已给）
  · 逆 VM 指令语义
  · 逆 selfcrypt 掩码算法
  · 逆 indirect 置换逻辑
  · 找授权判定点

【仍然必须做】
  1. 从**这一个具体二进制**提取 per-build 数据：
       期望值 / 密钥流初始态 / opcode 置换种子 / s_perm / 掩码
     -> 这些**不在源码里**，每构建随机生成
  2. 处理 selfcrypt 的**动态解密时机**（窗口解密，明文不驻留）
  3. 让**完整性校验自洽**（改了必须重算 CRC，且 watchdog 周期复查）
  4. 每遇**新构建**重做 1-3
```

**这就是方针的立足点**：源码给"原理"，二进制给"这一次的密钥"。
**成本 = f(每次构建的增量工作量)**。

---

## 3. ⚠️ 致命弱点实测：per-build 秘密**可被 diff 直接定位**

### 3.1 实测数据

**实验**：同一份源码，用随机种子构建两次，逐字节对比。

```
产物: 229376 字节（两次大小相同）
差异: 637 字节 = **0.28%**

差异分布（4KB 块）:
  偏移 0x023000-0x024000 : 589 字节   <-- 集中
  偏移 0x02C000-0x02D000 :  32 字节
  偏移 0x02B000-0x02C000 :   8 字节
  偏移 0x000000-0x001000 :   4 字节
  偏移 0x032000-0x033000 :   4 字节
有差异的块: 5 / 56
```

**差异区域落在哪个节**：

```
0x23000 -> .rdata   (节内偏移 0x1600)
0x2C000 -> .rdata   (节内偏移 0xA600)
```

### 3.2 这个数据意味着什么（对攻击者）

> **攻击者拿到同一程序的两个构建**（两个客户的拷贝、或旧版+新版），
> 一次 `binary diff` 就能：
> 1. **定位全部 per-build 数据**（0.28% 的差异点）
> 2. **看出"哪些字节是秘密"**（变化的即秘密）
> 3. **针对该区域定向分析**

### 3.3 为什么这对本方针是**实质削弱**

| 方针原意 | 若不修的话实际 |
|----------|---------------|
| 攻击者"每次都要大量工作" | 源码已公开 → 理解成本 0 |
| | 秘密位置**已知** → 定位成本 ≈ 0 |
| | **增量工作可能只剩"读一小段已知位置的数据"** |

### 3.4 加剧因素：**节名直接泄露用途**

实测节表：

```
.protxec   XR     <-- "protected executable"? 一看就知道
.protcrc   R      <-- "protected CRC"          ← 直接点名完整性校验
.protcry   WR     <-- "protected crypto"       ← 直接点名密文区
.protpad   R      <-- 填充（暗示上面是真货）
.fptable   WR     <-- 函数指针表                ← 直接点名
```

> **攻击者甚至不需要 diff** —— 节名已经把"该看哪里"告诉他了。
> 这是"设计保密"思维的遗留，在完全开源方针下**必须清理**。

---

## 4. 必须补的四项（让方针真正成立）

> 目标：**攻击者完全知道原理，仍必须做大量工作**。

### 4.1 让 diff **无法定位**秘密（最高优先）

| 手段 | 做法 | 效果 |
|------|------|------|
| **节名随机化** | 每构建生成随机节名（如 `.x7f3a` / `.q2m9`）| 消掉"看名字就知道用途" |
| **差异扩散（padding 随机化）** | 每构建随机填充非秘密区域 | 让"变化的=秘密"**不再成立** |
| **秘密位置随机化** | 秘密数据在节内随机偏移 + 分片存放 | diff 无法聚焦 |
| **诱饵（decoy）** | 主动制造**假的变化区域** | 攻击者无法区分真假 |

**关键指标（可验收）**：
```
目标: 两次构建的差异字节占比 从 0.28% 提升到 **> 30%**
      且差异**均匀分布**（无集中块）
```
> 这样 diff 就**不再是定位工具** —— 攻击者无法区分"per-build 秘密"
> 与"随机噪声"。

### 4.2 让"提取秘密"本身需要动态分析

| 现状 | 问题 | 改进方向 |
|------|------|----------|
| 秘密以**数据结构**存在于 `.rdata` | 静态可读 | 让秘密**只在使用时动态推导**（如从多个常量 + 运行期值合成）|
| 期望值是**明文常量** | diff 即得 | 期望值分片 + 与其它值混合存储 |
| `s_perm` 是**明文数组** | 同上 | 由 seed 在运行期**现算**，不落静态表 |

### 4.3 提高"改完还得让它跑"的成本

| 手段 | 说明 |
|------|------|
| **完整性覆盖扩大** | 现有 3 段 CRC（`.text`/`.rdata`/`.pdata`）→ 让被改的每一处都被覆盖 |
| **watchdog 周期复查** | 已实现；可提高频率/随机化间隔 |
| **交叉校验** | 多个独立机制校验同一事实（改一处不够，要改全部）|
| **CRC 交织** | 让 CRC 之间互相依赖（改一个需重算链）|

### 4.4 简化 VM 的同时**不降低动态成本**

**你的"简化 VM"诉求是合理的**，但需区分两件事：

| VM 的复杂度来自 | 开源后价值 | 处置建议 |
|-----------------|-----------|----------|
| **指令集大小**（47 个 opcode）| ❌ **低** —— 源码公开，攻击者可读 | ✅ **可以简化** |
| **等价路径多样性**（`var[]`/`sem[]`）| ✅ **高** —— 制造动态不确定性 | ⚠️ **保留** |
| **窗口加密执行**（明文不驻留）| ✅ **高** —— 迫使动态分析 | ⚠️ **保留** |
| **调度间接化**（`g_routes`/`dt[]`）| 🟡 中 —— 静态可读但动态仍绕 | 可简化 |
| **抗静态分析手法**（1a-1d）| ❌ 低 —— 静态手法在源码公开后失效 | ✅ **可简化** |

**结论**：
> **简化的应该是"指令集与静态混淆手法"（源码可读 → 无价值）；
> 必须保留的是"运行期不确定性"（窗口解密、等价路径、per-build 置换）。**
>
> 换句话说：**把"静态难读"换成"动态难测"** —— 这与 Kerckhoffs 完全一致。

## 5. 修改后的成本模型（方针成立的条件）

```
攻击者成本 = 理解成本 + 定位成本 + 提取成本 + 改造成本 + 验证成本
              ↑            ↑          ↑          ↑          ↑
完全开源后:   ≈0          ↑↑↑        ↑↑         ↑↑         ↑↑
                          (§4.1)     (§4.2)     (§4.3)     (§4.3)

目标: 前三项之和 >> 理解成本的节省
即:   定位成本必须**高于**理解成本（否则开源白送）
```

**当前实测**：定位成本 **≈ 0**（0.28% diff + 节名泄露）→ **方针未成立**
**修完 §4 后**：定位成本可提升到"必须动态分析"级别 → **方针成立**
