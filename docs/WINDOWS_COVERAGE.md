## 1. 集成模型：**源码级框架**（不是加壳器）

这是理解覆盖率的前提。实测 SDK 骨架：

```
prot_sdk/skeleton/
  app_main.c         保护壳入口（不要改）
  business_stub.c    业务模板（你写这里）
  prot_shell.h       业务契约
  build_skeleton.ps1 构建
```

业务契约：

```c
int prot_business_main(const prot_business_ctx* ctx);
```

**含义**：

| 特性 | 本项目 | 典型加壳器（VMProtect/Themida）|
|------|--------|--------------------------------|
| 集成方式 | **改源码 + 重编译** | 包装**已编译 exe** |
| 需要源码 | **是** | 否 |
| 语言限制 | **C 与 C++**（均已实测；C++ 需 `extern "C"`，已内建于头文件）| 语言无关 |
| 源码可控性 | 高（可细粒度保护函数）| 低（只能整体加壳）|
| 对客户 | 开发者 | 开发者或发行者 |

> **这是本项目的根本定位**：**源码级保护框架**，不是黑盒加壳器。
> **它不能保护你手上已有的 exe** —— 必须能重编译。

## 2. 各形态实测结果

### 2.1 ✅ 控制台程序（CONSOLE）

```
项目原生支持: demo/main.c、骨架 app_main.c、示例 tool_demo
实测: 全部构建 + 运行通过（门禁 14/14）
```

### 2.2 ✅ GUI 桌面程序（WINDOWS 子系统）—— **实测通过**

这是**覆盖率的关键问题**（大量商业软件无控制台）。

**实测方法**：构造 `WinMain` 程序 + 链接**真实保护库**（antidebug/syscall/strcrypt）

| 测试 | 结果 |
|------|------|
| GUI 裸程序构建 | ✅ 103936 字节 |
| **GUI + 真实保护库** | ✅ **113152 字节** |
| **GUI 程序实际运行** | ✅ 生成结果文件 `detected=0 peb=0 port=0` |

**结论**：**保护库无 CONSOLE 依赖**，GUI 程序可正常接入并执行保护逻辑。

**但有一个现状限制**：

```
build.ps1:  /SUBSYSTEM:CONSOLE × 5 处,  WINDOWS × 0 处
骨架模板:   只有 CONSOLE 模板
```

→ **能保护 GUI，但没有现成的 GUI 模板** —— 用户需自行改子系统与入口点。
这是**体验缺口**（不是能力缺口）。

### 2.3 ✅ DLL 动态库 —— 实测通过

```
实测: cl /LD 编译包含保护库的 DLL -> ✅ 成功
```

### 2.4 ✅ **C++ 项目 —— 原为缺口，已修复**

**修复前实测证据**（本次评估最重要的发现）：

```
C++ 项目 #include "protect/antidebug.h"
  -> error LNK2019: 无法解析的外部符号
     ?prot_antidebug_detected@@YAIPEBUprot_antidebug_report@@@Z  (C++ 修饰名)
```

**根因**：14 个头文件缺 `extern "C"` 保护（34 个函数声明）。

**修复**（2026-09-21）：为 14 个头文件加标准保护：

```c
#ifdef __cplusplus
extern "C" {
#endif
    ... 函数声明 ...
#ifdef __cplusplus
}
#endif
```

**修复后实测**（同一份测试代码，修复前正是它失败的）：

| 项 | 修复前 | 修复后 |
|----|--------|--------|
| C++ 链接 | ✗ LNK2019 | **✓ 149504 字节** |
| 运行 | — | **✓ `cpp ok detected=0 peb=0`** |
| C 构建（门禁）| 13/14 | **13/14（未受影响）** |

> ⚠️ **仍待验证**（不因链接通过就认定完全可用）：
> · 保护库（纯 C）与 C++ 运行时（异常/RAII）共存
> · C++ 的 `.text` 布局是否影响 selfcrypt 页冲突判定
> → 标注"待验证"，不预设成功。

### 2.5 ⬜ Windows 服务

`docs/HANDOVER.md` 有相关记录（`nssm` 部署驻留守护）。**未单独测试**

### 2.6 ❌ 内核驱动（.sys）—— **设计外**

本项目是**用户态**保护。驱动需要不同技术栈，且边界 **B5** 明确说明
"用户态无法防内核级攻击"。**不支持，且不在路线图内**。
