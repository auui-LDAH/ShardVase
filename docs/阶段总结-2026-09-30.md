### 3.7 ⭐ **判据失败时留下的证据，比判据本身更值钱**

`tools/gate_log.ps1`（本阶段最后落地）。起因是一次实测事故：门禁报「1/29 未通过」，
但调用方只截了输出末尾几行 → **失败项名与详情永久丢失** → 此后连跑 **5 轮无法复现**。

```
机制: 门禁 / ci_linux 每轮用 `Start-Transcript` 落盘 `build/logs/<name>_<时间戳>.log`
      （实测: Write-Host 裸调用 / `& { … } | Out-Null` 内 / Check 内部详情行 /
       [ok]`/`[X]` 行 / Write-Output —— 全部落盘；无需改写门禁里上百处 Write-Host）
实证: 一轮 31 项门禁的日志 2762 B，含红项行、`FAIL: 1/31 未通过`、转录结束行。
```
**两条诚实边界**：① 日志记的是门禁**自己的控制台输出**，被 `Check` 内 `| Out-Null`
吞掉的**子进程 stdout 不在其中**（现在至少能定位**哪一项**失败，详情需单独重跑该项）；
② 子进程的 `Write-Host` **不进父进程转录**（故门禁自检换子进程跑时，自检横幅不在日志里）。

**踩坑（同型于 verify_lock 自检删掉门禁自己的锁）**：转录是**会话级**的 ——
自检在同一会话里 start/stop 会**掐断门禁这一轮的日志**，恰好毁掉本工具存在的理由。
对策：检测到外层转录时**自检自动换子进程**运行（门禁输出里会打印
`[gate_log] 检测到外层转录 -> …`）。**新机制自己必须有正向对照**
（"开启后写的行必须落盘"）—— 否则"日志里没有"分不清是**没写**还是**没记**。

## 4. R3.2 的结论（**先反向、后更正 —— 本节保留两次结论**）

> ⚠️ **本节的 §4.2/§4.3 第一版结论（"守卫无效"）已于当日晚些时候被推翻，**
> **正确结论见下方 §4.4。保留错结论是纪律要求 —— "记录会过时"是本项目已记名 6 次的形态。**

### 4.1 发现（R3.2-a，**静态分析，成立**）

`src/integrity.c` 的段 CRC **先清零 selfcrypt 掩码区**（`build_selfcrypt_mask`）
-> **掩码区内的判定点改它不影响 CRC**。实测归属：

| 判定点 | .text 偏移 | 在掩码区 | patch 被 CRC 抓到 |
|--------|-----------|---------|------------------|
| **`prot_integrity_check_self`** | +7488 | ✅ | ❌ **不** |
| **`prot_license_verify`** | +11776 | ✅ | ❌ **不** |
| `prot_antidebug_detected` | +22192 | ❌ | ✅ 会 |
| `prot_dbiguard_suspicious` | +8880 | ❌ | ✅ 会 |
| `prot_vmdetect_suspicious` | +624 | ❌ | ✅ 会 |

**两个高危缺口**：
```
① patch `prot_integrity_check_self` -> 完整性防护被**静默关闭**
   根因: 校验器**自己**落在掩码区 = **不在自己 CRC 的覆盖范围内**（自我指涉缺口）
② patch `prot_license_verify` -> 授权恒通过且不被 CRC 抓到
```

### 4.2 实施（第 1/2/4 组）与**否定性验证**

```
第1组: `prot_integrity_check_guards`（序言快照比对）+ 看门狗集成
第2组: 注册式扩展（覆盖 license/dbiguard/vmdetect）
第4组: `guard_selftest` 入库门禁（29 项）
```
**决定性验证**（判据 = `g_guard_hits`）：
```
对照（不 patch）: hits = 0   ✅ 无恒报
5 个判定点逐一 patch: hits **全部 = 0**   ❌ **守卫未命中任何目标**
```

### 4.3 结论与处置

```
· **R3.2-b 未产生可用加固** —— 代码在，但**有效性未证明且证据指向"无效"**
· `guard_selftest` 判据已改为 `g_guard_hits > 0`
  -> 门禁第 29 项**现在会 FAIL** —— 这是**诚实的失败**，保留以防假阳性再混过
· 已提交内容的影响**如实标注**（`DECISION_REDUNDANCY_PLAN.md` §10.5）:
    c7df177「实测抓住函数头 patch」-> **不成立**（是 .text CRC 的功劳）
    b7f9f96「正向+负向可自证」-> **负向是假阳性**
· **其中一项仍有效**: R3.2-a 的掩码区归属（静态分析，可复现）
```

### 4.4 ✅ **更正（2026-09-30 晚）—— 守卫确实有效；§4.2/§4.3 是测量假象**

```
§4.2 的"5 个判定点 hits 全部 = 0" **不成立** —— 三次探查全是**测量错误**:
  第1次 map 正则形态假设错 -> 只解析出 948/2989 个符号 -> "符号被优化掉了"
  第2次 用偏好基址 0x140000000 去读 -> ASLR 生效(真实 0x7FF6860A0000)
        -> 全部 err=299 -> "变量不存在"
  第3次 采样间隔 120ms，而 hits 的**自增与 terminate 在同一 tick 内**(微秒级)
        -> 必然错过 = §4.2 那张表的来源
真实根因(src/integrity.c:163-173): `prot_selfcrypt_enter` 失败 -> `continue;`
        **整轮跳过** -> 掩码区内目标(license_verify/check_self)的 patch 改了**密文**
        -> selfcrypt 自己的 per-region CRC 先失败 -> 守卫(L211)**根本没跑**
```

**决定性实验**（把运行期 `g_wd_policy` 置 CONTINUE = 模拟"段 CRC 已被中和"，
**先写预测再测**）：四项预测**全部命中**：

| 用例 | `g_guard_hits` | `g_wd_tamper` | 预测 |
|------|---------------|--------------|------|
| 对照 | 0 | 0 | ✅ |
| ① antidebug_detected | 0→1→2→3 | 每 tick **+2** | ✅ |
| ② dbiguard_suspicious | 0→1→2→3→4 | 每 tick **+2** | ✅ |
| ⑤ vmdetect_suspicious | 0→1→2→3 | 每 tick **+2** | ✅ |
| ④ license_verify(掩码区内) | **0** | 每 tick **+1** | ✅ |

```
=> **判定点序言快照校验机制正确且有效**；hits:tamper 的 1:2 / 0:1 比值
   与三种 tick 路径**定量吻合**，无残余未知。
=> `tools/guard_selftest.py` **重写后 PASS（正向 0 / 负向 3）**；
   门禁第 29 项不再是红项（§5 的"预期 FAIL"同时作废）。
=> 旧版 selftest 选 `prot_license_verify`（掩码区内）= **必然永远 FAIL**，
   且原因会被误读为"守卫失效" —— 文件头"目标必须选掩码区内"的结论**是反的**。
=> 新增纪律: 任何"读不到 / 恒为 0"的结论，**必须先用一个已知非零的靶子
   证明读取链路是通的**（本次对照 = `g_guard_dyn_n=3`）。
```

**出厂 EXIT 策略下的诚实边界**：掩码区外目标由**段 CRC 先终止**(L175)、
掩码区内目标由 **selfcrypt 先拦截**(L163) —— 守卫**不是第一发现者**；
它的价值在于 **"段 CRC 被中和（重算）后仍有第二道"**（= DRILL7 L100 记的待办）。
**EXIT 策略下的端到端演示仍未做** → 留给 R3.2-d / DRILL9。
详见 `docs/DECISION_REDUNDANCY_PLAN.md` **§11**。

## 7. 本阶段的元结论

```
① **记录会过时**（本阶段又 3 次: 杠杆表第 5 行 / V1 / S4）—— R1 的 docclaim 正是为此
② **判据比实现更难**，且**判据的错会更隐蔽**（R3.2 花了 6 个提交才发现判据是假阳性）
③ **"已记名的坑"不等于"已消除的坑"**（脚手架四处漏加引号）
④ **诚实边界是资产**：推翻自己的结论、保留红的门禁项，
   比"看起来全绿"更接近项目的方针（让破解者付出真实成本，而非让我们自己安心）
⑤ ⭐ **"读不到" ≠ "不存在"**（本阶段最贵的一条 —— 我在**一小时内连犯三次**）:
   map 正则形态假设错 / 用偏好基址读 ASLR 后的进程 / 采样间隔比事件间隔大
   => 对策: 任何"读不到 / 恒为 0"的结论，**必须先用已知非零的靶子证明链路是通的**
   => 而且 **④ 本身要小心**: 若"诚实失败"是**测量假象**，
      它会变成**假的反向结论** —— 比假阳性更难发现，因为它看起来"诚实"。
```
