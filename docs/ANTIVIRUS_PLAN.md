## 1. 背景与目标

### 1.1 现状
- protect 使用自修改（selfcrypt 原位加密）、VM 运行期解密写内存、字符串
  加密——这些行为与恶意软件特征重叠，易触发**静态扫描与行为拦截**；
- 已有 Release 输出收敛（`PROT_RELEASE_CONCEAL`、W4）但未经过**真实杀软
  环境实测**；
- 兼容性：只真机 Win11 24H2 验证过；Win10/低版本未测，评估者大概率使用；
- 无签名包的"未知发布者"评级会加剧误报（有自签 pfx 可降低，但无信任根）。

### 1.2 目标
1. 建立**实测矩阵**：Win10 21H2 / Win10 22H2 / Win11 23H2 / Win11 24H2
   × [Defender / SmartScreen / 360 / 火绒 / 腾讯电脑管家] ×
   [demo.exe Release / demo.exe Dev / hashcalc.exe 演示包] × [签名/未签名]；
2. 依据实测**降低误报**：产出构建侧收敛补丁（特征源盘点+最小改动）；
3. 产出**申诉流程文档**（各厂商误报提交渠道与材料清单）；
4. 产出**公开证据页**（compatibility & AV record），并入 README/Landing。

## 3. 误报降低策略（依实测结果排序）

| 策略 | 成本 | 说明 |
|------|------|------|
| RELEASE 收敛开启（已有）| 0 | 输出/错误可见性最小化 |
| 特征源盘点修复 | 中 | selfcrypt 写执行窗口、VM blob 明文长度、字符串加密表特征 |
| PE 常规化（节名/头/资源）| 低-中 | 去掉 `.protcrypt` 等非常规节名（改默认名）、图标/版本资源齐全 |
| 签名+申诉 | 低 | 自签 pfx（已有）；正式申诉需代码签名证书（缺钱，先自签+申诉）|
| 厂商误报提交 | 低 | 360/火绒/腾讯/微软 WDCI 提交流程文档化 |

**原则**：绝不为"过检"牺牲保护强度（不做无修饰的哈希变异躲扫描）；只收敛
无害特征与正规申诉。

## 6. 验收标准
1. 矩阵表格完整（≥12 环境×样本组合，记录到报毒名）；
2. 若存在可低成本修复的误报，补丁落地并复测收敛；
3. 申诉文档含 4 家渠道+材料清单；
4. 公开页上线（并入 README 链接），如实记录结果（含未解决项）。

## 7. 风险与回退
| 风险 | 缓解 |
|------|------|
| 部分误报无法根除 | 如实公开+申诉跟进（不装看不见）；文档说明行业通例 |
| VM 构建/测试耗时超预期 | 并行 3 VM；先 2 环境跑主矩阵 |
| 修复引入回归 | 每次补丁跑 attack_sdk_matrix 回归 |
| 伦理边界被误读 | 页首声明"合法软件误报治理，不做恶意载荷免杀" |

**回退**：全部新增（样本/矩阵记录/文档），删除即回退；改动仅限构建侧
特征，不动保护核心。
