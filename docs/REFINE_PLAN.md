## 1.5 ⚠️ 实施 R1.1 时**新踩的环境陷阱**（记名，供全局沉淀）

```
现象: 自检的"篡改-恢复"用 `open(p,'w',encoding='utf-8')` 写回 ->
      `publish/01-*.md` **换行被静默改成 CRLF**（内容相同、字节不同）
      -> git 报文件被修改（我**改坏了受跟踪文件**）
根因: Python 文本模式在 Windows 默认 `newline=None` ->
      **把 `\n` 翻译成 `\r\n`**
对策: ① 自检的篡改-恢复必须**字节级**（`'rb'`/`'wb'`）
      ② 加 **T5b 断言**（恢复后字节必须与原一致）—— 自检**不得改坏仓库**
      ③ 恢复受跟踪文件时**用真实路径**（`glob`），不要用
         `git status --porcelain` 的输出（**非 ASCII 路径是八进制转义**，
         实测导致 `git checkout` 报 pathspec 不匹配 -> 恢复失败）
```
> **教训归属**: 与 `safe-ops-backup` 同源 —— **"写回必须精确"**；
> 且**测试代码本身也在"改仓库"**，必须受同一纪律约束。

## 2. 目标与范围

### 2.1 目标（可验收）

```
R1 决策留痕: 建立"**文档断言 ↔ 实测**"的**自动一致性检查**，并回填 §1 的漂移
R2 可用性:   补齐**部署加固**（消除 B）与**性能基准**（填补"未测量"）
R3 对抗职能: 补上 **函数头 patch 防御**（消除 A），并复核 PARTIAL 存量
```

### 2.2 范围（**做什么**）

| 方向 | 内容 |
|------|------|
| **可用性** | ① 部署加固工具（ACL 自动设置 + **实测阻断验证**）② 性能基准（启动开销/常驻内存/跨组合对比）③ 接入向导与文档核查 |
| **对抗职能** | ① **构建期 `.text` 布局随机化**（补 0 杠杆）② 关键判定点冗余 + 交叉校验 ③ PARTIAL 逐条实测复核 |
| **决策留痕** | ① **文档断言检查器**（新增门禁项）② 关键文档"最后核实"元数据 ③ 漂移回填 |

### 2.3 **明确不做**（防范围蔓延）

| 不做 | 理由 |
|------|------|
| **二进制加壳**（处理无源码 EXE）| **定位不变**；是另一条产品线，非"完善" |
| 在线时间锚点（`USABILITY §6` 第 1 优先）| 需**服务端**且与"备案期间公网停止"冲突 -> 独立线，本轮不做 |
| 内核级防护（`KERNEL_DRIVER_ASSESSMENT`）| 评估已完成，实施是**另一量级** |
| 模块协议 / 跨平台延伸（§6 第 4/5）| 成本高，且当前无阻塞 |
| 判定逻辑下沉 VM（路线 B 机制 3）| 中成本、收益需先由机制 1/2 数据决定 -> **本轮先不启动** |

## 3. 分步计划

> **顺序 = 留痕机制 -> 可用性快赢 -> 对抗能力增量**
> 理由：**R1 是元能力**（不先建，R2/R3 又会制造新漂移）；
> R2 低风险且**直接消除最脆弱前提**；R3 风险最高（踩已知雷区）、收益最大，放最后。

### R1 —— 决策留痕机制（**先做**）

| 步 | 交付 | 验收 |
|----|------|------|
| R1.1 | **`tools/docclaim_check.py`**：文档断言 ↔ 实测 一致性检查器<br>内部 `CLAIMS` 表（`id / 断言 / 来源文档 / 探针 / 期望`）<br>首批断言 ≥6 条（见下）| **含负向自检**（≥3 负向）：<br>① 断言期望被反转 -> 必须 FAIL<br>② 来源文档不存在 -> 必须 FAIL<br>③ 探针抛异常 -> 必须 FAIL（不崩溃）|
| R1.2 | **入库门禁**（第 **26** 项）+ ci 镜像 | 门禁 **26/26**；ci PASS |
| R1.3 | **"最后核实"元数据**：给 6 份关键文档加<br>`> **最后核实**: YYYY-MM-DD · 方法 · 提交` | 6 份具备；doccheck 检查格式 |
| R1.4 | **回填 §1 的 3 处漂移**（1/2/3）| 回填后 docclaim 全绿 |

**首批断言（设计要点：只断言"可机械验证"的事实）**：
```
① SCDBG 不在 Release 产物中          <- 二进制搜索
② SCDBG 不在 Linux 产物中            <- 二进制搜索
③ 门禁项数 == N                      <- 数 Check 块
④ ci 运行时项数 == M                 <- 数 results.append
⑤ ATTACK_MATRIX BREACHED 计数 == K   <- 解析矩阵表
⑥ 宿主指纹 == b4281468e21a4033       <- 运行 demo --version（Windows 基线）
```
> **为什么这能治漂移**：把"文档说的话"变成**可执行断言** ——
> 一旦实测与文档不符，**门禁直接失败**（而非等人发现）。

## 5. 风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| **R3.1 踩"布局敏感"雷区** —— `S1` 已证（`revoke` **同页**、`.text` CRC **原子性缺陷**）| **高** | ① **先只随机化"填充"**（不动函数顺序）作为最小步<br>② 每步跑 **3 连建** + 完整门禁<br>③ 失败可**独立回滚**（seed 固定即回到当前行为）|
| R3.1 破坏可复现性 | 中 | 随机化**必须由 seed 驱动**（沿用现有体系）；`repro_check` 作为门禁项 |
| R2.1 ACL 加固**干扰合法用户**（升级/写配置失败）| 中 | ① 只加固**二进制与嵌入资源**所在目录，**不动数据目录**<br>② 提供 `-WhatIf` 与回滚<br>③ 文档写明"升级流程需临时提权" |
| R2.1 管理员可绕过 ACL | —— | **如实入册**（ACL 是"提高门槛"非"保证"）|
| R1 断言表本身失效（探针过时）| 中 | 断言**含负向自检** + 每条断言标明"探针"与"期望"，**变更断言必须改文档来源**|
| 文档"最后核实"变成形式主义 | 中 | 元数据**必须含核实方法**（命令/工具名），否则 doccheck 报错 |
