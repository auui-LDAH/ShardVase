## 1. 背景与目标

### 1.1 决策
- 放弃 B2B 直接找订单（太费精力）；
- 用 GitHub 建立"技术信任 + 演示可下载 + 内容引流"的三位一体存在；
- 目标：**第一个月 50-100 star / 每周 1-2 篇内容 / 3-5 个有效咨询**。

### 1.2 原则：开源度划分（诚实两难）
| 内容 | 公开? | 理由 |
|------|-------|------|
| 演示二进制（hashcalc + 保护后的 demo）+ 评估授权流程 | ✅ | 可下载、可自己破解试试——最强的说服力 |
| 保护原理白话文档/能力表/边界诚实页 | ✅ | 建立专业信任，与竞品差异化 |
| 攻防记录（轮次总结、结论，不含攻击工具代码）| ✅ | 实证型内容，翻译成文章素材 |
| **保护内核源码（vm/selfcrypt/间接表等）** | ❌ | 公开=直接武装破解者，且违反商业利益 |
| **攻击工具（vm_reduce/procdump/attack_drill）** | ❌ | 同上，绝不开源 |
| prot_sdk 向导/骨架 | ⚠️ 部分 | 文档公开；骨架模板在"注册评估后获取"或订阅制内 |

ShardVase-website/        # 可选：landing.html → GitHub Pages

### 2.2 内容引流（docs/marketing/ 是我的产出）
- 系列文章 1：《你的软件 30 秒就被 dump，然后呢？》（第四轮实证）
- 系列文章 2：《授权不该一把密钥走天下：私钥/台账/哈希链》 （第五轮+落地）

- 发布到：GitHub Discussions + 知乎/掘金/V2EX（一文多发）

### 2.3 成交入口（不强推，自然发生）
- Issues 模板（咨询单）：邮箱/QQ 可选；
- README 末段"需要实施服务？"一句 + 报价链接（指向商业文档包）；
- 演示包内附"评估流程"（发 .req → 我们签发 7 天评估 → 试用到期可询价）。

## 3. 决策点
| 编号 | 决策 | 选项 | 推荐 |
|------|------|------|------|
| D1 | 公开范围 | 仅文档+演示 / 加攻防总结 / 加 prot_sdk 文档 | **文档+演示+攻防总结**（Aristotle：没有工具代码）|

## 5. 验收标准
1. 公开仓库可访问：README/三页文档/演示包 Release 齐备；
2. 演示包下载后按说明可跑通（评估授权闭环）；
3. Pages Landing 可访问且含完整 CTA（试用/咨询/边界）；
4. Issues 模板就绪，咨询入口可收信；
5. 3 篇文章初稿可发。

## 6. 风险与回退
- 内核/工具误公开 → 本计划明确红线，发布前清单检查；
- 演示包被二次转卖 → 许可声明+水印（hashcalc 提示"评估版含机器绑定"）；
- Pages/行动受限 → 全部文件本机有副本，随时可迁徙；
- **回退**：全部文件为新增目录 docs/marketing + 公开仓库内容，删除即回退。
