## 0. 一句话

**本项目 100+ 次调试里，同一批动作被反复手写**（找符号 → 算运行时地址 →
读写目标进程内存 → 解释退出码 → 读内部计数器），每次都写临时脚本、
每次都可能踩同一批坑（路径空格、blob 路径、反调试干扰、编码）。
**把它们做成一个控制台 = 把调试经验固化为工具。**

## 2. 设计目标

```
一个 **单文件 CLI**（`tools/prot_dbg.py`），提供:
  $ prot_dbg sym <name>                  # ① 符号 -> 链接时 VA（+ .text 偏移 + 掩码区归属）
  $ prot_dbg run [--args ...]            # ⑦ 正确启动（自动补 --vm-blob，避免 45323 坑）
  $ prot_dbg patch <sym> [--pid P]       # ②③ 运行时 patch（ASLR 自动换算）
  $ prot_dbg read <sym> [--len N]        # ④ 读运行时内存
  $ prot_dbg watch <sym>                 # 读它（含 static 计数器）
  $ prot_dbg exit <code>                 # ⑤ 退出码解释（从 protdef.h 解析，不硬编码）
  $ prot_dbg mask <sym>                  # ⑥ 掩码区归属
  $ prot_dbg doctor                      # 环境体检（构建产物/符号/blob/权限）
```

### 2.1 **关键设计纪律**（都来自实际踩坑）

| 纪律 | 来源 |
|------|------|
| **退出码解释从 `protdef.h` 解析** | R1 的 `docclaim` 教训：硬编码会漂移 |
| **`--vm-blob` 自动补全** | perf_baseline 实测 rc=45323 |
| **路径一律用绝对路径 + 引号** | 仓库路径含空格（R2.3 四处缺陷） |
| **所有输出 `encoding='utf-8', errors='replace'`** | cl.exe 中文输出致 UnicodeDecodeError |
| **判据输出"命中计数"而非"进程是否死"** | **本轮 §10 教训**：进程死会被任何同向检测满足 |
| **显式提示"本工具自身可能触发反调试"** | **本轮**：219 由 OpenProcess 触发，差点误判 |
| **不改仓库状态**（只读 + 目标进程内写） | 自检纪律（自检不得改坏仓库） |

### 2.2 **与既有工具的分工**（**不重复造**）

| 已有 | 职责 | 本工具关系 |
|------|------|-----------|
| `tools/attacker/winpe_sympatcher` | 攻击者视角的符号解析 + 内存 patch（**演练用**）| **本工具是防御方调试用**；语义重叠处**直接复用**其 `symparse`/`mempatch` 思路，不新写解析器 |
| `tools/guard_selftest.py` | 特定守卫的行为自检（门禁项）| 本工具可**辅助其定位**（`sym`/`mask`/`watch`）|
| `tools/mutate_check.py` | 检查器变异测试 | 无关 |
| `-DPROT_INTEGRITY_DEBUG` 构建 | 内部诊断输出 | 本工具可**包装**该构建（见 §3 第 3 步）|

| 项 | 内容 |

| 风险 | 中（写远程内存；但**只作用于调试目标**）|

#### 第 2 步 — ✅ **已交付**（2026-10-01，`tools/prot_dbg.py` + 门禁第 32 项）

| 项 | 结果 |
|----|------|
| 子命令 | `read <符号> [--len N]` / `patch <符号> [--bytes "31 C0 C3" \| --nop N \| --restore]` / `watch <符号> [--seconds S] [--patch <符号>…]`；活体通用 `--pid P` / `--no-keep-alive` / `--no-adwarn` |
| 验收① 一条命令 | `watch g_guard_hits --seconds 6 --patch prot_antidebug_detected` 实测：预置看门狗策略 + patch + 观测压成**一条命令**（原 4 轮试错）。输出 `[3.01s] 00 00 00 00 -> 01 00 00 00`，结论「变化 1 次」 |
| 验收② 读回验证 | `patch` 打印 `写入前 / 期望 / 读回` 三行 + `✓ **读回验证通过**`；`--restore` 同样读回一致 |
| 验收③ 无权限明确报错 | `--pid 999999` -> `(process) Win32 87`；`--pid 4`(System) -> `(permission) Win32 5 ACCESS_DENIED`；不存在符号 -> `(symbol) 不在 map 中` + 4 条原因。**三类各自分类，绝不静默退化成 0** |
| **ASLR 自动换算** | `Target.rt(link_va) = base + (link_va - PREF)`；输出 `链接时 VA 0x140001000 -> 运行时地址 0x7FF6BA121000 (映像基址 0x7FF6BA120000；ASLR 滑动 +0x…)`——**绝不允许把链接时 VA 直接当运行时地址用** |
| **读回验证的真实理由**（2026-10-01 实测更正） | 曾断言"`.text` 只读，WPM 会**返回成功却没写进去**"—— **实测未复现**（映像 `SEC_IMAGE` 写时复制页，RX/RWX **不阻止** WPM；真正拒绝的是**私有**页 `R`/`NOACCESS`，`err=998`）。故 WPM 返回值**可信**；读回验证保留，理由改为 ① 防**部分写入**（`n.value < len(data)`）② 防从 `ok` 误推语义。**教训: 把没验证过的机制当结论写进注释比不写更危险**——此处是自检把我自己的错误断言抓了出来 |
| 自检 | `--selftest-live` **L0–L5 全 PASS**（L1a 文件同址基准正向对照 / L2 读回 / L3 不存在符号必须失败 / **L4 私有只读页必须拒绝（err=998）** + **L4b 同页解锁后必须写成功**（没有 L4b，L4 的"失败"可被"地址非法"解释，就没有判别力）/ L5 同址不变量必须报"无变化"） |

## 5. 与 R3.2 的关系（**优先级**）—— 2026-09-30 当日更新

> ⚠️ **本节原判断已被实测推翻**。原话："§10.4 的定位**正需要第 3 步**"。
> **事实**：§10.4 **已于当日用只读探针查明**，**未使用** `-DPROT_INTEGRITY_DEBUG` 构建。
> 根因 = `src/integrity.c:163-173` 的 `continue`：掩码区**内**目标被 patch 的是**密文**
> → `prot_selfcrypt_enter` 自己的 per-region CRC 先失败 → **整轮跳过** → `check_guards(L211)` 未执行。
> 完整证据见 `docs/DECISION_REDUNDANCY_PLAN.md` §11。
> （"记录会过时"在本项目已记名 7 次 —— 本条即为第 7 次，**保留原文供对照**。）

**这不是削弱本计划，而是换了一个更强的理由。**

R3.2 那一轮**用了 4 轮迭代、写了 11 个临时探针脚本**
（`v1_guardstate` / `v2_guardstate` / `v4_aslr` / `v6_focused` / `v7_mask` / `v8_mask2` /
`v9_policy` / `w1_decisive` / `y2_readback` / `y3_trace` / `y4_hits`），
其中**前三次失败全部是测量错误**，每一次都会在本控制台里被挡住：

| 本轮的实际失败 | 本控制台里本应由谁挡住 |
|---|---|
| map 正则形态假设错 → 只解析出 948/2989 个符号 → "符号被优化掉了" | `sym` + **`doctor`**（符号数须与基线比对，异常即报） |
| 用链接偏好基址 `0x140000000` 读 ASLR 后的进程 → 全部 `err=299` | `sym` / `read`（**内置 ASLR 换算**，不向用户暴露原始 VA） |
| 采样间隔 120ms ≫ 事件间隔（微秒级）→ "`g_guard_hits` 恒 0" | `watch`（**默认按 tick 对齐**，并打印采样率与观测窗口） |
| 差点把 `219` 读成"守卫失效"，实为**工具自身** `OpenProcess` 触发反调试 | **第 4 步的反调试提示** |

```
=> 优先级结论（**修正后**）: 先做 **第 1 步 + 第 2 步 + 第 4 步**
   （`sym`/`mask`/`exit`/`doctor` + `patch`/`read`/`watch` + 反调试提示）
   —— 理由从"解一个谜"变成"**把这一轮的 4 轮试错压缩成 1 条命令**"。

=> 第 3 步（诊断构建包装）**降级为可选**: 谜已解，但它仍是把
   "不可观测变可观测"的正规手段，留给将来（例如 DRILL9 端到端）。
```

  `_module_base`，`pid 4` 被误报成"进程可能已退出"、`pid 999999` 的 `err=87` 被 `_why` 默认
  归类成 `address`（把人引向"RVA 换算"错方向）—— 现改为**先 `OpenProcess` 定性**，
  按 `code == 5` -> `permission`、否则 -> `process`，显式盖掉默认的 address 归类。
- `exit` 子命令与 `prot_status` 状态码的**数值空间重叠**已由工具**显式告警**
