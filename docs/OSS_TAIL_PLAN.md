  其中 `src/crc32.c` 的 `#pragma code_seg(".protxec")` 需特别确认

## 3. 分阶段执行计划

### 阶段 A：历史重写（①）—— 最高优先级

**为什么最先**：不可逆，且必须在任何推送到本仓库之前完成。

| 步 | 动作 | 验证 |
|----|------|------|
| A1 | 提交当前未跟踪文件（`tools/add_license_headers.py`），确保工作区干净 | `git status` 干净 |
| A2 | 刷新 bundle 备份并**实际克隆验证**提交数一致 | 克隆出的 count == 当前 count |
| A3 | 试运行：在临时克隆上执行 `--rewrite` | 8 类字符串残留 0；提交数不变；可克隆 |
| A4 | 对**真实仓库**执行 `python tools/oss_release.py --rewrite` | 工具内置验证：泄露 0 + 身份统一 + 可恢复 |
| A5 | `python tools/oss_release.py --update-sha` 更新 112 处 SHA 引用 | `git diff` 仅含 SHA 变化 |
| A6 | 重跑完整构建 + 门禁 | **14/14** |
| A7 | 最终泄露复查（工作区 + 历史 + 身份） | `--check` 全绿 |

**回滚**：`git clone <bundle>` 重建（已验证可行）。

**风险与应对**：

| 风险 | 应对 |
|------|------|
| 重写破坏内容 | A3 在克隆上先验证；A6 跑完整门禁 |
| 备份不可用 | A2 强制验证可恢复，不符则中止 |
| SHA 引用失效 | A5 用 commit-map 自动更新；A7 复查 |
| 重写后 `filter-repo` 删除了 remote | 本仓库无 remote，无影响 |

**推荐串行顺序**：`A → B → C → D`

理由：
- A 最紧急（不可逆、推送前必做）
