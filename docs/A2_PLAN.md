# A2 自动 VM 化原型计划 — C 子集 → vasm 翻译器 (A2_PLAN)

> 版本：2026-08-28 v1 · 状态：**规划完成，未开工** · 定位：护城河工程
> 第一步——把"业务函数体 VM 化"从手写 vasm 变成**自动翻译**，这是与
> 竞品对标的关键差异（VMProtect 类的卖点），也是 prot_sdk 商品化的
> 分水岭。本次做**受限原型**（范围收敛、可验证、不依赖三方库）。

---

## 1. 背景与目标

### 1.1 现状
- vasm 指令集完整（栈式：算术/位/比较/跳转/基址内存 load8-64/store8-64/
  call/ret/R 寄存器/setcon，vmenc assemble 支持确定性种子构建）；
- 现有 VM 保护**只覆盖授权判定链**（demo/license_*.vasm 手写）；
- 业务函数 VM 化目前要**手写 vasm**——90% 的开发者做不到，这是
  prot_sdk 的准入障碍。

### 1.2 原型目标（诚实收敛）
1. 写 `tools/c2vasm.py`：解析 **C 子集单函数** → 生成 vasm；
2. 覆盖：uint32/uint64 局部变量、字面量、赋值、二元运算
   （`+ - * & | ^ << >>`）、比较（`< <= > >= == !=`）、`for/while`、
   `if/else`、`return`；**不含**：函数调用、指针/数组（除固定 mem 布局
   的 load/store）、IO、浮点；
3. 验证：同一函数"原生 C 编译结果" vs "VM 执行结果"逐字节一致
   （golden tests）+ 篡改立即数导致结果变化的对抗演示；
4. 输出文档：支持子集、限制、接入 prot_sdk 的下一步设计。

## 2. 技术设计

### 2.1 管线
```
.c 子集函数  → [c2vasm.py: lexer → recursive descent parser → IR] 
  → [代码生成: 栈式 vasm] → .vasm → vmenc assemble → blob → VM 装载执行
```

### 2.2 编译策略
- **变量布局**：固定帧布局——参数 `@0..`, 输出 `@32..`, 局部变量 `@64..`
  （每变量 8 字节槽）。VM 用 `setbase`+偏移寻址（与现有 vasm 模式一致）；
- **表达式**：栈式发射（A op B → push offset, load64, push offset2, load64,
  op），临时结果留在栈；
- **控制流**：`for/while` → 标签+jmp/jz；`if/else` → jz/反跳；
  比较结果按 C 语义（0/1 值，可选 setcon/brk 家族——原型用数值 0/1 push）；
- **64 位为主**：`push64`/`load64`/`store64`；助记符上限。

### 2.3 文件集
```
tools/c2vasm.py           翻译器（无三方依赖）
tests/c2vasm_golden.py    golden：原生(宿主 C 输出) vs VM 执行 逐项比对
demo/bizvm_fn.c           样例源（FNV 型函数，如 prot_business_calc 子集）
demo/bizvm_*.vasm         生成物（不提交，构建产物）
scripts/ 说明             README: 支持子集/限制/A2 下一步
```

## 5. 验收标准
1. 样例函数 ≥6 个（FFNV/u64 算术/位移/取模/冒泡式比较/条件聚合），
   golden 全部一致；
2. 篡改任一立即数 → golden 对比失败（证明 VM 内计算真实生效）；
3. 编译产物经 vmenc assemble 无错、可装载执行；
4. README 文档：语法支持表 + 限制 + A2 二阶段（接入 prot_sdk）设计。

## 6. 风险与回退
| 风险 | 缓解 |
|------|------|
| C 语法语义细节多（顺序点/整数提升）| 限定"无符号 32/64 参数"子集，语义简单化声明 |
| 栈平衡 bug | golden 对比兜底 + asm 反汇编检查（vm_reduce 模式）|
| 时间超限 | 先交付"无 if"v0（循环+算术），if/else 为 v0.1 |
| **回退** | 全部新增（tools/c2vasm.py + tests + docs），删除即回退 |
