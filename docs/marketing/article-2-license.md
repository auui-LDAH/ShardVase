# 授权不该一把密钥走天下

> 《ShardVase 攻防实录》第 2 篇 · 从"卖 key"到"审计的授权体系"

如果你卖软件，迟早会面对这三件事：客户换机、试用到期、授权被拿去多机
共用。很多方案的答案是"发个带密钥的文本文件"——然后呢？密钥没什么用。
我们把授权做成一条**可以审计的链**，每一步都有说法。

## 授权文件为什么"改不动"

我们的授权是一个文本文件，看起来平平无奇：

```
SERIAL=DEMO-2026-ABCDEFGH
MACHINE_ID=0x5e6bfd...
PRODUCT=PROT-DEMO-2026
TIER=1
EXPIRES=0
SIGNATURE=<512字符>
```

每个字段都参与 RSA-3072 签名。攻击者把 TIER 改成 2？验证失败。把
EXPIRES 改成 0？失败。把机器码改成自己的？失败——因为**绑定不在文本
里，在签名载荷里**：程序运行时用自己的硬件标识（卷序列号+机器 GUID+
磁盘物理序列号）构建消息去验签。文本里的 MACHINE_ID 只是给人看的注释，
真正锁死的是"某台机器 + 这把签名"。

实测矩阵（公开记录）：五类字段篡改全拒；换机必败。

## 签发本身要能审计

授权好发，但"谁、什么时候、给谁签了什么"如果只是一张可改的 Excel，
等于没审计。我们的签发体系有四个硬性机制，全部落地并测试过：

| 机制 | 作用 |
|------|------|
| 私钥只在签发方服务器 | 客户/开发机只有公钥，签不出来 |
| 防重放（按申请 nonce）| 同一个 .req 不能重复签号 |
| 台账哈希链 | 改/删任意一行记录都会被校验工具发现 |
| 字段卫生 | 注入逗号/换行伪造台账行被拒绝 |

## 到期与换机的诚实版

- **到期**：expires 进签名，过期即拒（这正是 C 端实测过的）。但它依赖
  本地时钟——回拨能复活，所以我们只说它是"防试用超期"，不吹成铁律；
  在线时间锚点在商业版路线里。
- **换机**：客户换电脑 = 重新申请 = 重新签发 = 台账多一行。不用你发
  "万能 key"，也不怕万能 key 被传播。

## 一句话总结

授权体系的三个支柱：**签名绑定（不可伪造）、私钥自持（只有你能签）、
台账可审计（事后查得清）**。少任何一根，授权就是摆设。
