# ShardVase demo v1.2.0 — 反逆向保护套件演示

> 演示包：这套保护本身的完整演示（反调试 → 完整性守护 → VM 校验链 →
> 机器绑定授权，一次运行全走一遍）。下载 Releases 里的 zip，解压后按本文件运行。

> ### ⚠️ 先读这一条：**在你的机器上首次运行会被拒绝**
>
> 包内的 `license.txt` 绑定了**签发机**的机器标识。在其他机器上首跑会看到
> `license: 0` → `序列号无效。` —— 这不是包坏了，而是机器绑定机制
> **按设计工作**（这正是你要评估的核心能力之一）。
>
> **三步跑通**：
> ```
> 1. 运行 demo.exe --vm-blob vm.blob     # 首跑被拒，但会打印你的机器标识
> 2. 开 Issue 附上机器标识               # 评估申请模板
> 3. 收到 license.txt 与序列号后替换文件，再运行
> ```

能力与边界：[ShardVase-docs](https://github.com/auui-LDAH/ShardVase-docs)

## 本包内容

```
demo.exe       反逆向保护套件演示（机器绑定 + 分级授权 + VM 保护链）
vm.blob        VM 镜像包（服务器签名，防替换）
license.txt    演示授权（**绑定签发机** —— 见文首说明）
ReadMe.txt     运行说明（含序列号）
SHA256SUMS     全部文件的 SHA-256 校验和
```

系统要求：Windows x64。

## 怎么跑通（必读）

1. 运行（先验证包完整性，可选 `sha256sum -c SHA256SUMS`）：

   ```
   demo.exe --vm-blob vm.blob --license-file license.txt
   ```

2. 非签发机会看到 `license: 0` → `序列号无效。` exit=1；
   屏幕上会照常打印 `机器标识:0x...`；
3. 开 [Issue：评估申请](https://github.com/auui-LDAH/ShardVase-docs/issues/new?template=eval.yml)
   附上该机器标识；
4. 我们会签发与你机器绑定的评估授权（含序列号）回传；
5. 替换 `license.txt`，输入签发回执中的序列号，应看到：

   ```
   license: 1 (tier=1 expires=...)
   校验通过，欢迎使用！
   ```

> **为什么不能预置一个"通用"授权？** 因为机器绑定就写在 RSA 签名载荷里 ——
> 一个能通过所有机器的授权，等于没有机器绑定。这条限制本身就是本产品
> 的核心能力（也是诚实边界的来源，见边界清单）。

## 不申请也能验证的部分（签发机上实测）

以下行为**无需有效授权**即可观察（均为实测结果），用来验证"保护是真实的"：

| 尝试 | 实测结果 | 说明 |
|------|---------|------|
| 篡改 `license.txt` 任意一个字符 | `license: 0` → `序列号无效。` exit=1 | 全字段参与 RSA-3072 签名 |
| 输入错误序列号 | `序列号无效。` exit=1 | 序列号校验在 VM 字节码中 |
| 用伪造/修改过的 `vm.blob` | VM 镜像装载失败 | blob 与授权同私钥签名 |
| 用调试器附加 | 反调试多维检测 | 干净环境零误报基线 |
| 反汇编 `demo.exe` 找授权判定 | 判定链在 VM 字节码中 | 47 条自定义指令集 |

> 注：把整个包拷到另一台机器 → 拒绝（机器绑定生效）。
