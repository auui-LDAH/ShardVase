## 1. 背景与目标

### 1.1 为什么现在攻签发链路
A-1 离线签发已上线（服务器 Ubuntu + RSA-3072 + GUI 签发台）。前四轮证明
**二进制保护**有效；但授权链的薄弱点可能在**流程/数据/工具**侧：
- 私钥与台账挂在脚本/文件层，攻击者若能偷私钥 = 全废；
- .req 无认证、license 纯签名绑定，攻击者可构造任意输入测解析器鲁棒性；
- 工具链（vmenc/verify_license/issue_from_req）被注入或误报 = 运营放水；
- 防御候选方向（失败时序、失败锁定、台账哈希链、schema 严校验）尚未实测。

### 1.2 目标
1. 攻击者视角对签发链路做 6 类攻击（S/L/V/T/D/O），实证每项结局；
2. 特别验证"伪造/篡改 .req 与 license 在绑定下是否自损"；
3. 顺带测得 4 个防御候选方向的可行性（不改产品代码的隔离评估优先；
   需改 demo 的列为决策点）；
4. 输出第五轮报告 + 更新 THREATMODEL/合同契约边界。

## 2. 攻击矩阵设计（6 类）

### S 签发端（服务器/私钥/流程）
| ID | 攻击 | 工具/手法 | 预期 |
|----|------|-----------|------|
| **S1** | 私钥泄漏路径盘点 | 检查服务器 keys/ 权限、备份副本、SSH 历史、进程内存、日志是否含密钥材料 | 权限已 600/备份在被控机=可接受；记录"私钥只增不减"纪律缺口 |
| **S2** | 无认证自动签发滥用 | 伪造 50 个 .req（脚本批量）模拟机器人 → 论证"自动签 = 垃圾授权洪泛" | 现有人工环节天然限流；量化：伪造 req 代价≈0，但换不回有效授权 |
| **S3** | .req 篡改造** | 改 machine_id/customer/nonce/时间 → 签发 → 目标机验证 | 改 machine_id=自损（该死机无授权）；非机器字段=运营噪音 |
| **S4** | 旧 .req 重放再签 | 拿历史 .req 重签一次 → 台账出现两条同机器记录 | 台账能发现（同一 nonce 重复）；是否应有重复检测（防御候选 D-D1） |
| **S5** | 台账销毁/篡改 | 删 issue-log.csv / 改其中一行（如改 tier） | 无密码学保护=审计可被事后清洗（诚实记录；候选 D-D2 哈希链） |

### L 授权文件（license.txt）
| ID | 攻击 | 工具/手法 | 预期 |
|----|------|-----------|------|
| **L1** | 字段大全伪造（3072 回归） | SERIAL/MACHINE_ID/TIER/EXPIRES/PRODUCT 逐一改 + 组合改 → demo 全部拒绝 | 全拒（verify 载荷任意字段参与签名） |
| **L2** | base64 鲁棒性 | 签名尾部加垃圾/去 padding/换行注入/超大 sig → demo 解析 | 解析器应拒（b64 解码失败 → license:0），实测 |
| **L3** | 公钥替换（embed key swap） | 改 demo 内嵌 pubblob/der → 攻击者自签 license → 通过？ | **已知边界 D2a 类复演**：单镜像可换=可自行授权；生产必须防写安装目录 |
| **L4** | 时钟回拨绕过 EXPIRES | 系统时间调回 → 过期 license 复活？ | 纯本地时间源=可回拨（边界；在线时间源是 D 期项） |

### V 验证/工具链
| ID | 攻击 | 工具/手法 | 预期 |
|----|------|-----------|------|
| **V1** | verify_license.py 假阳性 | 换公钥文件/缺字段/超长 sig/改 schema → 自查工具是否误报 VALID | 应保持 INVALID；工具自身鲁棒性 |
| **V2** | vmenc.py 参数注入 | keygen 路径穿越、serial 带换行/非 ascii、expires 负值/超大 | 应拒绝或无害化；serial 注入是否会破坏 license 格式 |
| **V3** | issue 日志注入 | customer/note 含逗号/换行 → csv 表结构破坏 | 台账数据完整性风险（诚实记录；过滤候选） |

### T 时序类
| ID | 攻击 | 工具/手法 | 预期 |
|----|------|-----------|------|
| **T1** | 失败返回时序指纹 | 统计 license 无效/机不匹配/过期三条失败路径耗时分布 | 当前失败立即返回（可被用于区分失败原因）；候选 D-D3 随机延迟 |

### D 防御候选方向（顺带实测）
| ID | 候选 | 形态 | 结论方式 |
|----|------|------|----------|
| **D-D1** | 签发重复 nonce 检测 | issue_from_req 检查历史 .req nonce | 评估：微信扫码? 直接拒重复 |
| **D-D2** | 台账哈希链 | issue-log 每行注入前一行 SHA-256 | 隔离评估（新脚本）+ 兼容旧台账 |
| **D-D3** | 失败响应时间混淆 | demo verify 失败后 sleep 随机 0-2s | 需改 demo（决策点）；隔离小工具仿真即可 |
| **D-D4** | .req schema/字段严校验 | 收窄类型/长度/格式 | 已有部分；补测边界 |
