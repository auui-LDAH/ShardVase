## 1. 背景与目标

### 1.1 为什么第三轮全绿不代表安全
第三轮 7 BLOCKED/0 BREACHED 说明**针对二进制本体的攻击手法**防御有效。
但 THREATMODEL 承认的剩余路径：
- **还原**：dump 明文 → 模拟器/符号执行还原 VM 字节码语义 → 构造绕过
  （"拿到全镜像也还原"是 VM 保护上限）；
- **取证**：完整进程转储（Procdump 风格）→ 离线分析解密后的引擎；
- **隐蔽**：仅挂 watchdog 线程（而非整个进程，C3 用的是 SuspendProcess）、
  ScyllaHide 全套反调试绕过。

### 1.2 目标
1. **实证还原成本**：写最小 VM 模拟器驱动还原 1 个镜像的语义——
   "还原需 X 时间"从估计变实测；
2. **实证取证难度**：完整进程转储 → 能否离线恢复引擎明文 + 重构校验输入；
3. **隐蔽性升级**：仅挂 watchdog 线程能否绕过复查（C3 的精确升级）；
4. **调试器全套绕过**：ScyllaHide 风格（PEB+句柄+计时+硬件断点清理组合）；
5. 输出"还原/取证/隐蔽"三类攻击的实证成本报告。

## 2. 第四轮攻击设计（还原/取证/隐蔽 3 类）

### R 还原类（VM 保护天敌）
| ID | 攻击 | 工具 | 预期 |
|----|------|------|------|
| **R1-4 VM 模拟器还原** | 写最小字节码解释器，装载 dump 的 VM 密文，用已知 key 解密 + 模拟执行，还原单个镜像语义（如 verify 的 compare 逻辑） | `tools/vm_reduce.py`（新，复用 vmenc 的 assembler 反操作） | 还原 verify 语义 = 证明"单镜像可还原"（PARTIAL，时间受限）；还原失败 = 成本高（BLOCKED 语义） |
| **R2-4 符号执行/污点** | 尝试用 angr（若无库则用简单约束求解）还原 serial→expect 的函数关系 | angr（可能无）→ 简化: 手工推导 | 验证"序列号校验是可推导函数"（设计已知，A1 签名是阻断点） |
| **R3-4 跨镜像级联** | 还原 3 个 VM 的中间数据流（h/total/result），验证"单镜像还原不足以通过" | 模拟器 + 数据流 | 单镜像还原不足以通过 = 多 VM 拆分有效 |

### F 取证类（完整转储）
| ID | 攻击 | 工具 | 预期 |
|----|------|------|------|
| **F1-4 Procdump 风格全转储** | ReadProcessMemory 全地址空间 → 写 minidump 式文件 → 离线分析引擎明文 | `procdump_like.py`（新） | 转储后离线可见引擎明文（D2a；D2b 构建间隙密文） |
| **F2-4 离线分析** | 对转储做字符串/结构扫描，恢复 demo_mem 现场（serial/result/license_ok） | python 解析 | **关键问题**：即使拿到全部现场，能否重放校验？——重放需 key/私钥，记录结论 |
| **F3-4 双 dump 对比** | 转储两次（正常/异常），diff 找校验分支 | — | 找到校验点 = 定位价值 |

### H 隐蔽类（绕过检测）
| ID | 攻击 | 工具 | 预期 |
|----|------|------|------|
| **H1-4 仅挂 watchdog 线程** | NtSuspendThread(主线程/CreateThread 返回的线程句柄) —— 不等同 SuspendProcess | `NtQuerySystemInformation/线程枚举` | 若仅挂 watchdog 线程有效 → 主流程继续 + 复查暂停 → 纵深缺口（BREACHED 候选） |
| **H2-4 watchdog 线程识别** | 枚举线程栈回溯找 watchdog 特征（Sleep 循环+TerminateProcess 引用） | 线程枚举 | 能否精准定位 watchdog 线程 |
| **H3-4 ScyllaHide 全套** | 清 PEB.BeingDebugged + NtQueryInformationProcess 拦截（改内存返回 0）+ 计时规避 | ctypes 写返回码 | 多因子检测是否全绕过 |
| **H4-4 硬件断点清理** | 清 DR0-DR3（攻击者清掉自己的痕迹） | 写 DR 寄存器（需内核，标记 SKIP/真实失败） | 记录：用户态无法清 DR——演示"硬件断点检测不可用户态绕过" |

### O 在线类（补充）
| ID | 攻击 | 工具 | 预期 |
|----|------|------|------|
| **O1-4 重放攻击** | mock 截获 /v1/check 响应 → 重放给另一个 session | 中间人代理 | 会话 seed 若固定=可重放；若随机=重放失效（N5 会话级设计） |
| **O2-4 降级攻击** | 强制离线（断网/黑名单 mock 不可达）→ 本地默认值 | 网络阻断模拟 | 离线可跑=设计（D2 离线优先），记录边界 |

## 3. 技术路线

### 3.1 R1-4 模拟器（核心新工具 `tools/vm_reduce.py`）
- 输入：dump 的 VM 密文 + key（从 blob/meta 提取）+ opcode 置换表（从
  vmenc.py 复算）；
- 处理：解密 → 逆置换 canonical opcode → 逐条模拟执行（栈式）→ **打印
  语义轨迹**（如 verify: load64(64) cmp load64(112) → result）；
- 输出：镜像的"伪代码"（证明引擎可还原）或"需要人工分析"（成本高）。

### 3.2 F1-4 转储器（`tools/procdump_like.py`）
- ReadProcessMemory 全映射（VirtualQueryEx 枚举）；
- 写原始 dump 文件（D2a 明文在场）→ 分析脚本提取引擎区。

### 3.3 H1-4 精确挂起
- 枚举目标进程线程（`NtQueryInformationProcess` → PEB → TEB 链 或
  Toolhelp `Thread32First/Next`）→ 找 watchdog 线程句柄 →
  `NtSuspendThread` 单线程。

## 6. 验收标准
1. R1-4 输出 verify 镜像语义轨迹（实证还原可行性或成本）；
2. F1-4 转储成功且离线可提取引擎明文（D2a）；
3. H1-4 精确挂 watchdog 结果（拦/破）明确；
4. H3-4 ScyllaHide 全套评估（多因子是否全绕）；
5. O1-4 重放结论（会话级设计是否防重放）；
6. 报告归档 + THREATMODEL 更新（还原/取证/隐蔽分类评估）。
