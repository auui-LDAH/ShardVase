> 版本：2026-08-14 v1 · 定位：把当前"演示级反逆向保护套件"推向**可交付/可销售**的
> 商业产品的完整计划。与既有文档的分工：
> `CONTRACT.md`=实现契约（怎么做）· `THREATMODEL.md`=威胁模型（扛多大成本）·
> `ROADMAP.md`=技术路线（Phase 1-5 进度）· `PRODUCTION.md`=已立项实施项（A/B 区）·
> `PLAN.md`=状态跟踪（进行到哪）· **本文=商业计划（卖什么、怎么交付、怎么运营、节奏）**。

## 1. 产品定义

- **一句话**：面向 Windows x64 原生软件的**代码保护 + 授权签发套件**——VM 代码保护、
  反调试、完整性、RSA 离线签发与分级授权一体，源码可见、无第三方运行时依赖。
- **对标**：Themida / VMProtect / CodeMeter 的**轻量自研替代**。差异化：不是黑盒
  混淆器，而是"复合门槛 + 每构建随机化 + 防伪造签名 + 断源装载"的可审计组合。
- **形态建议**（决策点 D1）：库 + 命令行工具链（当前形态）→ 可选做图形化保护器。
- **目标客户**：独立开发者、小规模商业软件、企业内部分发、代码审计培训。
- **价值主张**：
  1. 把单镜像破解成本抬到小时~天级，并让"生成合法授权"在信息论上不可行（RSA 离线私钥）；
  2. 每次构建互异，防批量 patch / 防通用还原器；
  3. 分发时 exe 与 vm.blob 分离，静态只拿 exe 无从分析（断源）。

## 2. 现状基线（2026-08-14，全部本地验证）

| 能力 | 状态 | 测试 |
|------|------|------|
| VM 代码保护（4 小 VM + 窗口解密 + 用后即焚 + 语义随构建变异） | ✅ | T5/T6、A2/A3 |
| 反调试（PEB/计时/蜜罐/堆特征/周期复查/direct syscall） | ✅ | T7/T11、A4、syscall_probe |
| 完整性（.text/.rdata/.pdata 三节 CRC + 看门狗） | ✅ | T4/T9/T10 |
| 授权（RSA-2048 离线签发 + 分级授权 tier + VM 门控） | ✅ | T1/T2/T8/T12、A1/A5/A6 |
| 断源（vm.blob 外部装载，exe 无 VM 逻辑） | ✅ | T13/T14 |
| 构建/验证基建（build.ps1 / verify.ps1 / manifest / 攻击模拟） | ✅ | 3 轮随机重建全绿 |

**与"商业"的差距**（详见 §3）：发行加固、可复现构建、真机兼容矩阵、吊销/在线能力、
签发与密钥运营 SOP、版本化与发布流程——这些尚未做或需环境。

## 4. 分阶段实施计划

> 原则：**阶段 I 全部本地可做可测**（不依赖真机/服务器/CI），是当前主线；
> 阶段 II/III 按资源到位后推进。每项都有验收标准，全部落在现有 verify 体系上。

### 阶段 I —— 本地完善（主线，立即可开始）

| # | 项 | 目标 | 验收 |
|---|----|------|------|
| I1 | 客户端吊销框架 | 黑名单文件（版本化，随 vm.blob 分发）+ 启动校验；支持离线降级策略与本地告警 | 新 e2e：黑名单命中 → 拒绝；缺失黑名单 → 策略化行为；全绿 |
| I2 | 发行加固 | signtool 自签证书签名；发布版剥离符号（/DEBUG:NONE + 无 PDB）；版本资源 + `--version`；`build.ps1 -Release` 开关 | dumpbin 检查：无调试目录/符号；签名有效；`--version` 输出正确 |
| I3 | 可复现构建 | `/Brepro`（同输入同产物，供审计）；manifest 含 blob 哈希/构建哈希 | 同种子两次构建产物 SHA-256 一致 |
| I4 | 兼容骨架 | Windows 版本检测/降级路径（API 可用性检查），Win10/11 分支代码就位 | 本机回归全绿；兼容矩阵留 II2 |
| I5 | 交付与运营文档 | CHANGELOG、发版 checklist、签发 SOP、客户台账模板、EULA 模板 | 文档评审通过；一次模拟发版全流程 |
| I6 | 测试面补强 | attacks.py 补 A7（tier 篡改）等；verify.ps1 展示 syscall_probe/blob 结果 | 全绿 |

### 阶段 II —— 真机验证（需 1 台普通 Windows 真机或非沙箱 Win VM）

| # | 项 | 验收 |
|---|----|------|
| II1 | T3 真机调试附加 | `python tests\e2e.py` T3 SKIP → PASS/FAIL，补用例 |
| II2 | 兼容性矩阵 | Win10 21H2/22H2、Win11、Server 2022 上跑 e2e+attacks 全绿 |
| II3 | 硬件绑定实机 | 两台机器换机验证 license 失效；克隆 VM 对比 |
| II4 | 长期驻留稳定性 | 24h 看门狗/周期复查零误报、内存无增长 |

### 阶段 III —— 服务端（可选，按商业化节奏）

| # | 项 | 说明 | 资源 |
|---|----|------|------|
| III1 | 签发中心 | Web/CLI 集中签发 + 审计日志（复用 vmenc 签名核心） | 极低规格 VPS（单核 512MB） |
| III2 | 在线验证 + 吊销 | 一个 `GET /check?serial&mid&tier` 接口 + 吊销 API；客户端已有 I1 降级框架 | 同上 + 域名/TLS |
| III3 | 客户门户 | 自助签发/续期/吊销查询 | 按需 |

> 决策点 D2：III 是否做、何时做——若以"离线优先"为卖点，III2 可为可选增值项。

## 5. 运营与安全（SOP 草案，I5 细化）

- **私钥分级**：主密钥（离线介质，双备份）→ 签发密钥（签发机）→ 从不进 CI/仓库。
- **签发记录**：每张 license 记 serial/mid/tier/时间/签发人/版本。
- **吊销策略**：黑名单先行（离线），在线吊销为可选增强；版本化 + 生效时间。
- **升级路径**：每客户独立构建 → 升级 = 重新构建 + 重新签发（旧 license 绑定 mid 不变则仍有效）。

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 私钥泄露 | 防伪造锚点崩塌 | 分级管理 + 离线存储 + 轮换流程（I5） |
| 兼容性误报（反调试误杀） | 客户流失 | 真机矩阵（II2）+ 咨询项只报告策略 + 可配置策略 |
| 破解/逆向进展 | 收入侵蚀 | 持续随机化 + 每客户独立构建 + blob 绑定升级（I1） |
| 法律/合规 | 分发受限 | EULA + 区域合规咨询（I5） |
| 单点（个人开发） | 进度风险 | 文档完备（本系列文档）保证可交接（HANDOVER） |

## 8. 决策点（需要用户拍板）

- **D1 产品形态**：库+CLI（当前）→ 是否做图形化保护器/插件？
- **D2 服务端**：阶段 III 是否立项？离线优先 or 在线增强？
- **D3 定价模型**：tier 已是 0/1/2（试用/正式/增值），正式定价策略？
- **D4 发布节奏**：阶段 I 完成后是否即"内部 v1.0"发版（自签证书）？

> 建议执行顺序：I1 → I2 → I3 → I5 → I4/I6（I1 价值最大：把"检测/保护"闭环到
> "授权生命周期"；I2/I3 是商业化外观与可审计性的底线）。
