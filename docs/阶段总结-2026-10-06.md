## 3. 技术沉淀（**本阶段新增**）

### 3.1 ⭐⭐ **判据里的"集合外常量"必须由集合推导**（同一缺陷**第 3 次**复发）

本阶段最后一轮，门禁第 14 项 `doccheck` 红在一个**与本次改动无关**的地方 —— 它自己的**负向自检**：

```
[doccheck] PASS                      ← 主检**过**
[doccheck-selftest] FAIL (5/20)      ← 自检**不过**
  [X] N 项漂移: 期望 1 条错误, 实际 0 条 ([])
  [X] 正确值不报: 期望 0 条错误, 实际 2 条 (['门禁项数声称 37, 实际 38'])
  [X] publish/01-关于ShardVase.md 里既无 `37/37` 也无 `37 项` —— 负向用例失去锚点
```

**根因**：自检用**硬编码字面量**验证"数字漂移必须被报错"——
`case('N 项漂移', 'release_check 35 项全通过\n', 1)` 的语义是「35 不在 `{GATE_TOTAL, GATE_DEFAULT}` 里」。
本轮 `GATE_DEFAULT` 由 34 变 **35** ⇒ `35` 在**改动同一刻**成了合法默认值 ⇒ "必须报错"的用例**零报错**。
同型第二处：真实文档锚点 `for good, bad in (('37/37','35/35'), …)` 找现值，而该文档本轮改成 `38/38` ⇒ 锚点**静默消失**。

**三次复发对照**：

| 次 | 时间 | 失效字面量 | 发现方式 |
|----|------|-----------|---------|
| ① | 早于本阶段 | `32` 变成合法默认值 | **人工**重挑 |
| ② | 2026-10-05 | `34 项` 变成合法默认值 | **人工**重挑（`36/33 -> 37/34`）|
| ③ | 2026-10-06 | `35 项` 变成合法默认值 | **门禁抓到**（`37/34 -> 38/35`）|

**修法**（`tools/doccheck.py`）：
```python
DRIFT = max(GATE_TOTAL, GATE_DEFAULT) + 1
assert DRIFT not in (GATE_TOTAL, GATE_DEFAULT), '漂移字面量不得落在容差内'
case('N/N 漂移',        '门禁 %d/%d 全通过\n' % (DRIFT, DRIFT), 1)
case('N 项漂移',        'release_check %d 项全通过\n' % DRIFT, 1)
case('正确值不报',      '门禁 %d/%d 全通过\nrelease_check %d 项\n'
                        % (GATE_TOTAL, GATE_TOTAL, GATE_DEFAULT), 0)
```

> **原则**：判据里凡是"**必须不落在某集合内**"的常量，都要**由那个集合推导**，
> 否则集合一变，判据**悄悄失去判别力**。这与本阶段 3.2 的 `TARGET_LOGICAL` 陷阱**同型**。

**判别力实测**（不是"看起来对"）：临时把 `DRIFT = max(...)+1` 改回 `DRIFT = GATE_TOTAL`
⇒ `--selftest` **rc=1**；还原 ⇒ `PASS: 21 项（8 项负向注入 / 13 项合规豁免）`。

### 3.2 ⭐⭐ **"表的条数对得上，语义对不上"** —— `TARGET_LOGICAL` 静默跳过

`.protxec` 的段名**每轮构建随机化**（`tools/gen_sections.py`）。而 CRC 目标表用一个
**常量** `TARGET_LOGICAL = (None, None, None, 'protxec')` 去查段名：

```
常量查找 'protxec' 与随机段名不匹配 -> next(...) 返回 None
  -> hashpatch: <name> section absent — skip
  -> CRC 字段保持 0 —— **无报错、门禁全绿、构建成功**
```

**计数型检查器（`doccheck`/`docclaim`）永远看不见它** —— 因为表的**条数**是对的，
错的是**语义**。⇒ 判据必须比对**实际元素**，不能只比**声明长度**。

### 3.3 ⭐⭐ **mock 目标的攻击结论不能外推**（DRILL7 真实闭环）

`docs/ATTACK_DRILL7.md` 原 §3 结论「盾永久失效」的**对象是 mock `test_target.c`**
（无完整性校验、无副本冗余）。本阶段对**真实 `demo.exe`** 重做四组：

| 组 | 操作 | 运行时 VA | 写入 | 退出码 | `完整性校验失败` |
|----|------|----------|------|--------|------------------|
| A | 基线（不附加、不写） | — | — | `1` | ✗ |
| D | 附加 + 符号定位，**只读不写** | `0x7ff6d37d1420` | ✗ | `1` | ✗ |
| B | patch `prot_antidebug_detected` 头 | 同上 | ✅ `31 c0 c3` | **`2989`** | **✓** |
| C | patch `prot_antidebug_detected_multi` 头 | `0x7ff6d37d15b0` | ✅ `31 c0 c3` | **`2989`** | **✓** |

四组均 `natural=True`（**无强杀**）。**根因**：两个函数的 `demo.map` 段号都是 `0001` = `.text$mn`，
而 `.text` 正是 `g_prot_baked_crc[0]` 的目标 ⇒ 改它**必然**被段 CRC 抓到 ⇒ `PROT_EXIT_TAMPERED`。

> **方法论**：**每条攻击结论都必须问「实证对象的哪些属性是这条结论的前提」**。
> mock 的前提是"无完整性校验"；真实目标有 `.text` 段 CRC —— 结论随之翻转。

**三条可外推判据**：
```
① 符号定位能力在真实目标上成立（MAP 通道给出编译时 VA，ASLR 换算后序言一致）
   ⚠️ 必须走 Toolhelp32 取模块基址 —— 拿 PREF 硬读会全部 err=299，采样为空，
      极易被读成"符号不存在"（此坑 guard_selftest 早有记载）
② 附加本身不再触发检测（组 D 只定位不写 = 与基线同为 exit=1，无 MSG_DBG）
③ patch 判定函数在真实目标上**不再静默生效**
```

### 3.5 ⭐ **只在失败路径执行的代码，是最难测的代码**

`tools/check_undef.py`（门禁第 37 项）**首次落地**就抓到两处**真实缺陷**：
`tools/guard_selftest.py` 的 `main()` 里引用了 `exit_pol`/`cont`，而这两个名字**局部于 `run_by_hits()`**。
它们**只在守卫未命中的失败路径**上被求值 —— 所有正常测试路径都不会碰到。

> **教训**：失败路径的代码没有"正常用例"覆盖它。**静态审计**才是它正确的防线，
> 运行期测试不是。这也是为什么第 37 项值得入门禁。

### 3.6 ⭐ **门禁的第三态：SKIP 不等于 PASS**

本阶段确立并反复实践 `未验证 != 通过`：
```
门禁 exit 0 = PASS / exit 1 = FAIL / exit 2 = SKIP（明确标注，不计入 PASS 分子）
```
**四处同型落地**：`release_check.ps1` 的 gated 项 · `android_compile_check.py`（找不到 NDK）
· `linux_compile_check.py`（WSL 不可用）· `tools/ci_sim.ps1` 的 `Step`。

⚠️ **踩到的陷阱**：`.github/workflows/ci.yml` 里照抄同 job 的 `set -e`，
而 `set -e` 会在**退出码 2（SKIP）时于 `rc=$?` 之前终止脚本** —— 把"未验证"误报成 job 失败。
> **`set -e` 与「我要看上一命令的退出码」互斥**；需要三态的步骤里必须二选一。

## 4. 专题结论：`guard_selftest` 的哨兵设计

**问题**：工具要证明"守卫能抓到 patch"，判据是 `g_guard_hits > 0`。
但守卫的看门狗**默认策略是 EXIT** —— 一旦侦测到篡改就**自杀**，计数来不及被读到。

**错误解法**：把 `g_wd_policy` 当就绪哨兵 ⇒ 工具自己写 `CONTINUE`，
**写早了会毁掉证据**（就绪与未就绪不可区分）。

**正确解法**：用 `g_wd_interval` —— 它**零初始化**、**只由宿主在参数校验后写一次**
（`src/integrity.c:828`）、**工具永不写它** ⇒ 非零即证明"宿主已过参数校验、看门狗已武装"。

```
SETTLE_S = 1.2          仅作为"PE 装载最短等待"
READY_TIMEOUT_S = 25.0  就绪哨兵超时
READY_SYM = 'g_wd_interval'
顺序: _wait_ready()  →  写 g_wd_policy = CONTINUE  →  施加 patch  →  采样
未就绪 ⇒ 短路（wrote=False, exit=None, hits=0）+ 杀宿主 + 返回
       ⇒ 主检用 `if r.get('ready') is False: okc = False` 拦成三态
```

> **可外推**：**用来证明"被测对象已就绪"的哨兵，必须是工具自己不会写的那个变量。**
> 否则工具的准备动作会污染它要观测的状态。
