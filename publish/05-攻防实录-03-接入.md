# 把保护做进产品：从 0 到受保护 exe 的接入实录

> 《ShardVase 攻防实录》第 3 篇 · 一个全新工程 5 分钟出受保护程序

"保护很强"和"我能接入"是两回事。我们给自己定的目标是：**一个开发者
从零开始，5 分钟内拿到一个被完整保护、带授权验证的可执行文件**。
这篇文章记录真实过程，包括踩的坑。

## 第一步：生成工程

`prot_sdk` 向导（图形界面）输入产品名、选密钥模式，生成一个骨架工程：

```
my_tool/
  app_main.c          保护壳（反调试/完整性/VM/授权门，不用改）
  business_my_tool.c  你的业务起点（就改这个文件）
  build_skeleton.ps1  一键构建
```

## 第二步：写业务

壳保证"授权门通过才进业务"，业务只管干活：

```c
int prot_business_main(const prot_business_ctx* ctx) {
    /* ctx->serial / ctx->machine_id / ctx->license_tier 可用 */
    if (ctx->license_tier >= 2) { /* 高级功能 */ }
    return 0;
}
```

## 第三步：构建 + 授权闭环

- 开发模式：构建自动生成密钥、自签、跑冒烟测试，全自动；
- 正式模式：嵌入签发方公钥构建 → 服务器补签 VM 镜像包 → 服务器签发
  license → 客户机运行。

实测输出（真机）：
```
license: 1 (tier=1 expires=1788...)
== 批量哈希校验工具 (正式版) ==
机器绑定: 0x... 授权: Tier1
```

## 踩过的坑（比成功更有价值）

1. **PowerShell 5.1 陷阱**：`param` 默认值不能调函数、脚本带中文必须
   UTF-8 BOM——三行配置能折腾半小时；
2. **`-D宏="值"` 引号经 cmd 丢失**：命令行传字符串宏被拆坏，最后用
   "字符串化宏"（`#x` 技巧）根治；
3. **WDAC/企业签名策略**：本机签名策略会间歇拦截全新的 exe（与保护
   无关），真机/无策略环境验收解决；
4. **VM 镜像包必须与授权同一把私钥签**——否则装上就被拒（这是设计，
   防镜像替换）。

## 结论

接入的门槛不是"理解保护原理"，而是**工具链顺不顺**。我们把顺的部分
做成了向导，把不顺的部分（签发流程、密钥纪律）写成了文档——欢迎下载
演示包自己跑一遍（首页 → 下载演示包）。
